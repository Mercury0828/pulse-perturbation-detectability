# PDET — Pulse-perturbation Detectability

A restricted-access detectability workflow for coherent errors in quantum control.

Given a control model and a measurement budget, PDET decides, for each candidate coherent error, whether it is
visible, hidden by the readout, hidden by the preparation, or hidden by the control; returns a low-cost
experiment that would expose a chosen hidden one; and reports the finite-shot cost of confirming it. The
diagnosis is a classical calculation on the control model and spends no device shots.

This repository holds the simulation code, the device campaign and the regenerated results for the manuscript
*"Which Coherent Errors Can You See? A Restricted-Access Detectability Workflow"* (submitted to *Quantum
Science and Technology*, IOP Publishing).

## Repository layout

- `numerics/` — the simulation code and the scripts that regenerate every simulation figure and table.
  - `pdet_core.py` — the validated core (toggling generators, restricted response matrix, kernel, margins).
  - `models.py` — transmon DRAG and cross-resonance control models.
  - `run_all.py` — single entry point that reproduces the full simulation result set.
  - `figstyle.py` — figure geometry and typography; every figure is authored at its final printed size.
  - `check_figure_legibility.py` — measures each figure PDF against the width the manuscript asks for and
    reports the printed point size; fails on bitmaps or Type 3 fonts.
  - `requirements.txt` — pinned dependencies.
- `hardware/` — the device campaign on `ibm_cleveland`: circuit construction, the predictions frozen before
  acquisition, the submission and analysis scripts, and the raw measurement counts for every job.
  - `RESULTS.md` — the measured results, per experiment, against the pre-registered predictions.
  - `results_hw/*.json` — raw counts with a provenance block per job (backend, resolved timing grid, qubit
    set, job identifier, charged processor time).
- `results/` — regenerated simulation data (JSON, fixed seed) and figures.

## Reproducing the simulation results

```bash
cd numerics
pip install -r requirements.txt
python run_all.py
```

Every figure is regenerated by a single named script under the fixed seed `20260628`. A correctness gate
validates the closed-form response against exact propagation before any result is produced: the maximum
relative error stays below `7e-8` across every model in the suite, and reaches `1.4e-10` on the two-level
reference case, against a pass requirement of `1e-4`. The run exits nonzero if any module fails.

Pinned environment: Python 3.11.4, NumPy 1.26.4, SciPy 1.16.1, QuTiP 5.1.1, Matplotlib 3.8.4, Stim 1.16.0.

## Reproducing the device figures

The archived measurement records are in the repository, so the analysis and the figures regenerate without
device access:

```bash
cd hardware
python analyze.py "results_hw/h2_ibm_cleveland_*.json" --readout-error 0.006
python make_paper_figures.py
```

Re-acquiring the data needs an allocation on `ibm_cleveland`; see `hardware/README.md`.
